# Accord Benchmark

An NLP/LLM benchmark suite for **Smart Legal Contract (SLC)** tasks, built from the
open-source [Accord Project](https://templates.accordproject.org) Cicero template library.

This project is part of an MSc dissertation (UCL, MSIN0114) in collaboration with
Docusign / the Accord Project.

## What it does

It measures how well language models perform legal-specific contract tasks, by putting
the **same fixed questions to multiple models** (a benchmark, not a single-model
evaluation). Models currently evaluated: **Gemini 2.5 Flash, Claude Haiku 4.5,
GPT-5.4-mini** (a matched fast tier).

## Tasks

| # | Task | What the model does | Status |
|---|------|---------------------|--------|
| 1 | Clause classification | identify the contract type from clause text |  implemented |
| 2 | Variable extraction | pull structured variable *values* from prose |  implemented |
| 2b | Type mapping | assign each variable its Concerto *type* (bridge to task 3) |  implemented |
| 3 | Model generation | generate the full Concerto data model from a clause |  implemented |
| 4 | Logic synthesis | generate the executable contract logic | ⏳ planned |
| 5 | FSM generation | generate the contract's state machine (lifecycle) | ⏳ planned |

Task 3 additionally covers compiler **validation** (via the real Concerto `ModelManager`),
**round-tripping** (self-correction from compiler feedback, with an iterations-to-valid
metric), and a **one-stage vs two-stage** generation comparison.

## Data

- **51 real templates** from the Accord Cicero library — the benchmark that headline
  results are reported on.
- **89 synthetic templates** generated to broaden domain coverage — reported **separately**
  and treated as secondary. They are known to be contaminated (generated by a Claude model,
  primitive types only), so they are never blended into a single "140" headline number.
- The template library is **pinned** to a fixed commit (see `TEMPLATE_LIBRARY_PIN.md`), and
  every results file records that commit, so all numbers are reproducible.

## Repository structure

```
scripts/                 generate / validate / evaluate per task, plus stats + figures
data/                    the benchmark questions (JSON, one file per task)
synthetic-templates/     the 89 generated templates (Accord folder structure)
results/                 model outputs + scores, split per model (gemini/ claude/ gpt/)
figures/                 charts (generated from results/)
data_baseline_51/        frozen "before expansion" questions (51 real only)
results_baseline_51/     frozen "before expansion" results
TEMPLATE_LIBRARY_PIN.md  the pinned library commit + how to reproduce
```

## Running

Each task follows a **generate → validate → evaluate** pipeline. Model choice is an
environment variable:

```
# generate the benchmark questions from templates
python3 scripts/generate_variable_extraction.py

# evaluate a model (BENCH_MODEL selects the model)
BENCH_MODEL=anthropic/claude-haiku-4.5 python3 scripts/evaluate_variable_extraction.py

# statistics (real vs synthetic split, significance tests) and charts
python3 scripts/compute_stats.py
python3 scripts/make_comparison_figures.py
```

Requires an `OPENROUTER_API_KEY` in a local `.env`, Python (numpy/scipy/matplotlib), and
Node with `@accordproject/concerto-core` for Concerto validation.
